# ios-b1lte

**iOS 26 on the Samsung Galaxy S10 (`beyond1lte`, SM-G973F, Exynos 9820)**

Apple's open-source XNU kernel running on a Galaxy S10 and booting the **unmodified iOS 26 userland** (launchd, system daemons, backboardd, SpringBoard) from the phone's own storage.

**Today:** the phone boots to the iOS home screen with touch and Wi-Fi; Settings, Control Center and several apps open. Safari loads pages, iOS plays sound on the speaker and on Bluetooth headphones. The interface is drawn by the Mali-G76 through Metal (about 16–37 fps); Liquid Glass still renders too light on light wallpapers.

> [!WARNING]
> Experimental research project, not a product. Apple's security policies (AMFI, code signing, Secure Enclave) are relaxed for hardware bring-up. Installing iOS **erases Android's `userdata` partition**, and a wrong partition write can brick the phone. Read [docs/installation.md](docs/installation.md) before flashing anything.

## Hardware Architecture

| Component | Galaxy S10 hardware | Port driver & subsystem |
| --- | --- | --- |
| **SoC** | Samsung Exynos 9820 (8 nm) | Board layer `B2LPlatformExpert`; Apple device tree generated by `XnuLoader` |
| **CPU** | 8 cores, 3 clusters: 2x Mongoose M4, 2x Cortex-A75, 4x Cortex-A55 (ARMv8.2-A) | PSCI SMP, GIC interrupts, cluster-aware placement; arm64e instructions (PAC, JSCVT, RCPC…) emulated in the kernel |
| **GPU** | ARM Mali-G76 MP12 | `B2LMaliService` / `b2l_mali_core` (from HakiOS) + Mesa panfrost/Bifrost compiler + Metal driver (`userspace/metal`) |
| **Display** | 6.1" AMOLED, 3040 × 1440, panel s6e3ha9 | `B2LFramebuffer` on the UEFI GOP framebuffer |
| **Touchscreen** | Samsung `sec_ts` Y771 (`hsi2c@104B0000`) | `B2LInput` HID digitizer |
| **Audio** | Exynos ABOX + 2x Cirrus Logic CS35L40 | `B2LAudio` + AudioServerPlugIn in `userspace/audio-plugin` |
| **Wi-Fi** | Broadcom BCM4375 | `B2LWifi` + `apple80211` bridge for `wifid` |
| **Bluetooth** | Broadcom BCM4375 (UART HCI) | `B2LBluetooth` (H4 relay for bluetoothd) + BlueTool stand-in dylib |
| **Storage** | UFS | Native UFS transport; HFS+ root on `userdata`; native cache on SYSTEM |
| **Memory** | 8 GB (~7.1 GB usable) | Fixed RAM bank list (`b2l_ram_ranges.h`) |
| **Boot chain** | Samsung S-Boot, bootloader unlocked | [beyond2lte UEFI](https://github.com/orhunnx/beyond2lte-uefi) (Project Mu) → `XnuLoader` boot menu → XNU |

## Boot Methods

### Method 1: BOOT partition image (current)
The kernel, the UEFI firmware and its embedded `XnuLoader` are packed into an Android boot image (`scripts/package-boot.py`) that S-Boot loads from the `boot` partition. `XnuLoader` builds the Apple device tree, shows a [boot menu](docs/boot-menu.md), then jumps into XNU.

## Getting Started

### Quick start
For someone who already has the toolchain and the IPSW:

```bash
cp .env.example .env                              # set paths, then export them
bash tools/b1l/b1l-build.sh 0001 b2l-metal-v1     # kernel → BOOT image → SYSTEM → BOOT, every write read back
bash tools/b1l/watch-build.sh                     # follow each stage live
```

### 1. Prerequisites
- Galaxy S10 **SM-G973F** with an unlocked bootloader and TWRP (root ADB).
- A Mac with Xcode and the iOS 26.5 **Kernel Debug Kit** (25F71); see [docs/build.md](docs/build.md).
- `adb`, Python 3 and `llvm-mc` (paths in [.env.example](.env.example)).
- The iOS 26 IPSW **23G90** (iPhone 16 Pro Max). It is never redistributed.
- A full partition backup made with `tools/flash-kit/backup-partitions.sh`.

### 2. Extract Device Firmware Blobs
Wi-Fi/Bluetooth firmware, NVRAM and calibration files come from your own phone and are never committed:

```bash
tools/flash-kit/check-device.sh   # phone in TWRP with root ADB
# TODO: commands that copy the BCM4375 firmware and NVRAM to $S10_PORT/device-s10/wifi-bt-fw/system
```

### 3. Prepare XNU and the Loader
```bash
scripts/fetch-xnu.sh     # pinned Apple XNU source
scripts/prepare-xnu.sh   # applies patches/ and copies xnu-overlay/
scripts/build-efi.sh     # XnuLoader (builds the Apple device tree at boot)
```

### 4. Build the iOS Root Image
```bash
tools/b1l/build-ios-root.sh       # HFS+ USERDATA image from the IPSW
tools/b1l/build-system-image.sh   # SYSTEM image with the translated native cache
```

### 5. Flash & Boot
Use `tools/b1l/b1l-build.sh` (above) or `tools/flash-kit/flash-images.sh`. Only BOOT (`sda14`), SYSTEM (`sda25`) and USERDATA (`sda34`) are ever written; see the [partition map](tools/flash-kit/docs/partition-map.md). If something goes wrong: [docs/troubleshooting.md](docs/troubleshooting.md).

## Repository Structure

```
├── common/          # Code shared by the loader and the kernel (SMP, memory)
├── docs/            # Documentation (see the table above)
├── patches/         # Patch series applied on Apple open-source XNU
├── scripts/         # Kernel, EFI, Mesa/Metal builds, packaging, log readers, host tests
├── tests/           # Host tests (C and Python)
├── tools/
│   ├── b1l/         # Build/flash loop, delta flashing, progress watchers, dyld cache tools
│   ├── flash-kit/   # Device checks, partition backup, guarded flashing
│   └── scan-isa.py  # Counts post-ARMv8.2 instructions in the dyld cache
├── uefi/            # XnuLoader (boot menu, device tree, Spleen font) and BootSurvey
├── userspace/       # iOS-side libraries: Metal driver, Mesa glue, audio plug-in
└── xnu-overlay/     # Board drivers and files copied over the XNU tree
```
